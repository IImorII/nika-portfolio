# VERONICA — interactive portfolio

React, TypeScript and Vite portfolio. The archive is generated from folders during every production build, including the existing GitHub Pages deployment.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведен в терминале. Команда `dev` автоматически пересобирает сайт после изменений; обновите страницу в браузере. `npm run dev:vite` запускает Vite с автоматическим обновлением страницы, включая добавление и удаление категорий, проектов и файлов.

```bash
npm test
npm run build
npm run preview
```

## Добавление категорий и работ

На телефонах проекты открываются и закрываются сразу: без разбивания банки, вылета/возвращения ягоды и кругового раскрытия. Частицы и ягоды внутри банок неподвижны; частицы вокруг банок при нажатии не создаются. Этот режим применяется к узким экранам, устройствам с сенсорным указателем и небольшим экранам в альбомной ориентации. На всех устройствах просмотр проектов закрывает весь экран сплошным фоном и скрывает главную страницу; при закрытии восстанавливается её положение прокрутки. Симуляции в банках приостанавливаются, пока открыт просмотр проектов или ABOUT.

Единственный источник каталога — папка `public/assets`:

```text
public/
  assets/
    packaging/
      jar/
        base.webp
        layer_1.webp
        layer_2.webp
        manifest.json
        settings.json
      works/
        media expert/
          section_1/
            01 overview.jpg
            02 detail.png
          section_2/
            03 motion.mp4
        another project/
          section_1/
            01.jpeg
    illustration/
      jar/
        base.webp
        layer_1.webp
        layer_2.webp
      works/
        book cover/
          section_1/
            01.png
            02.jpg
```

- Каждая папка непосредственно в `public/assets` — категория. Её название отображается жирным шрифтом рядом с банкой при наведении или выборе с клавиатуры, а также на странице категории.
- Банка хранится в папке `jar` рядом с `works`: `base.webp` — основа без этикетки, `layer_1.webp`, `layer_2.webp` и далее — остальные слои в порядке наложения. Все изображения должны иметь одинаковые размеры и прозрачный фон; не обрезайте слои по отдельности. Слои с `placement: "interior"` (внутренняя заливка и нарисованные ягоды) рисуются поверх основы, затем идут анимированные частицы и SVG-черника, затем этикетки, тени и ткань с `placement: "foreground"`. Без `placement` слой считается передним.
- `manifest.json` хранит исходные имена слоёв и режимы наложения (`normal`, `multiply`, `lighten`, `luminosity`, `color-burn`). Маски, эффекты и прозрачность Photoshop уже включены в WebP. Photoshop-режимы `LINEAR_BURN` и `DARKER_COLOR` преобразуются при экспорте в эквивалентные текстуры; их исходный режим отмечен в манифесте. Зависимые слои, обтравленные по полупрозрачной этикетке, экспортируются вместе с ней. Белые служебные фоны исключаются. Без манифеста все слои используют `normal`; файлы сортируются по числам (`layer_2` раньше `layer_10`).
- `glassPolygon` в манифесте задаёт внутренний контур стекла: пары `[x, y]` в диапазоне от 0 до 1 относительно размеров изображения. Контур исключает ткань, завязки и края независимо от их цвета. Движение учитывает весь размер частиц, их пульсацию и размер черники. Исходные контуры семи банок хранятся в `scripts/jar-glass-regions.json` и включаются при повторном экспорте PSD; для новых банок без контура используется консервативная нижняя область.
- Для совместимости поддерживается одиночное PNG/WebP прямо в папке категории с `jar` в имени, включая файл без расширения с корректным PNG/WebP-содержимым. Приоритет: `jar/base.webp`, затем `jar.webp`, `jar.png`, затем первый другой файл по имени. Категория без основы или одиночного изображения пропускается с предупреждением.
- Каждая папка непосредственно внутри `works` — проект. Заголовок берётся из названия папки. В отображаемых названиях категорий и проектов `-` и `_` заменяются пробелами: `media-expert` и `media_expert` отображаются как `media expert`. Повторные пробелы объединяются; имена папок и пути к файлам сохраняются.
- Внутри проекта создайте папки `section_1`, `section_2` и далее. Каждая папка — один слайд карусели, показывающий все файлы этой секции одновременно. Поддерживаются `.jpeg`, `.jpg`, `.png`, `.webp`, `.svg`, `.gif`, `.avif`, `.mp4`, в том числе расширения в верхнем регистре. Остальные файлы, скрытые папки и вложенные папки внутри секций игнорируются.
- Для порядка проектов добавьте в конец имени папки суффикс `#1`, `#2` и далее: `Salut_Hola #1`, `Mad_Dog #2`. Проекты с номерами идут первыми по возрастанию числа (`#2` перед `#10`); суффикс не отображается в названии на сайте. Проекты без номера идут после них в обычном порядке по именам. При одинаковых номерах порядок также определяется именем. Нумерация независима для каждой категории; имена папок и пути к файлам сохраняются.
- Категории, секции и файлы сортируются по имени с учётом чисел: `section_2` идёт перед `section_10`, `2.jpg` — перед `10.jpg`. Для управления порядком работ используйте `01`, `02` и т. д. Файлы в корне проекта поддерживаются для совместимости и показываются отдельным первым слайдом.
- Для приоритета размера контейнера добавьте тег в имя файла перед расширением: `cover #1.jpg`, `detail #2.png`, `motion #3.mp4`. Меньший номер даёт больший приоритет, файлы без тега имеют обычный приоритет. Можно поставить тег в другой части имени (`#1 cover.jpg`, `3#1.jpg`); если тегов несколько, используется наименьший положительный номер. Порядок медиа остаётся алфавитным: теги не используются для сортировки. Среди работ с близкими пропорциями контейнер с `#1` должен быть самым большим, `#2` — не меньше контейнеров с более низким приоритетом. Это обязательное условие выбора раскладки. Алгоритм сохраняет последовательность и одинаковые зазоры, затем выбирает наименьшую обрезку среди подходящих вариантов. В отличие от номера папки проекта, тег файла влияет на размер, а не на порядок.
- Текущие работы распределены по секциям до шести файлов, прежние вложенные группы видео и изображений вынесены в отдельные секции. Это только начальная организация: можно свободно переносить файлы между секциями и добавлять любое количество работ. Журнал перемещения с контрольными суммами находится в `temp/section-migration.json`.
- Пробелы, кириллица, `#` и `%` в названиях поддерживаются. Пути корректно учитывают адрес репозитория на GitHub Pages.
- Количество банок равно количеству найденных категорий с подходящим изображением `jar`. Раскладка рассчитывается автоматически; при большом каталоге главная страница становится прокручиваемой.
- Пустые категории и проекты показывают сообщение `Works coming soon.`. Для сохранения пустой папки в Git можно добавить `.gitkeep`.

Семь PSD из `temp/jar-1.psd` — `temp/jar-7.psd` экспортированы в категории `print`, `illustration`, `commercial`, `packaging`, `poster`, `digital`, `lettering` соответственно. Скрытые и пустые слои не отображаются и перечислены в манифестах. Старые `public/jars` и `public/projects` больше не являются источником каталога.

Повторный экспорт после изменения PSD: установите зависимости из `scripts/requirements-jar-layers.txt`, затем запустите `python scripts/export-jar-layers.py` из корня проекта. Скрипт сохраняет исходные PSD, экспортирует каждый видимый слой отдельно в WebP без потерь, применяет обтравочные маски и записывает режимы наложения для браузера.

Никаких изменений `src/data.ts` для добавления контента не требуется. После изменения папок выполните новую сборку/деплой: статический сайт обновляет каталог во время сборки, а не при загрузке страницы посетителем.

Размеры всех изображений и MP4 автоматически читаются при сборке и записываются как `width`/`height` в JSON внутри модуля каталога. Учитываются EXIF-поворот изображений, отдельный кадр анимации и поворот видео. Слайдер заранее рассчитывает окончательные контейнеры по этим размерам: загрузка файлов не меняет расположение работ. При изменении размера окна раскладка адаптируется. Отдельный JSON вручную поддерживать не нужно; после замены файлов размеры обновляются при следующей сборке. Если размеры файла прочитать нельзя, сборка остановится с указанием его пути.

Для изображений сборка также создаёт маленькие WebP-превью (до 32 px по длинной стороне), встроенные в каталог. При открытии секции или полноэкранного просмотра превью показывается сразу, без отдельного сетевого запроса. После загрузки и декодирования оригинала изображение плавно становится чётким за 300 мс, не меняя контейнер. При ошибке загрузки оригинала превью остаётся видимым. Прозрачность и EXIF-поворот сохраняются; у анимаций превью содержит первый кадр. Режим уменьшения движения отключает плавный переход.

Для MP4 такие же превью генерируются из первого кадра с учётом поворота видео. FFmpeg устанавливается автоматически как зависимость сборки через `@ffmpeg-installer/ffmpeg`; в браузер и опубликованный сайт его бинарный файл не попадает. Превью сразу показывается в секции и на полном экране и плавно исчезает только после декодирования кадра видео, а не после загрузки метаданных. При ошибке загрузки превью остаётся видимым. Для обновления превью после замены MP4 выполните новую сборку.

## Подпись проекта

В корень папки проекта (рядом с `section_1`, `section_2` и т. д.) можно добавить опциональный `copyright.json`. Подпись отображается справа снизу только при просмотре выбранного проекта, включая полноэкранный просмотр его работ. Пример уже есть в `public/assets/commercial/works/Media_Expert#1/copyright.json`:

```json
{
  "text": "© Media Expert",
  "font": "Helvetica, Arial, sans-serif",
  "size": 12,
  "color": "#75736e"
}
```

`text` — обычный текст (переносы строк задаются через `\n`); `font` — CSS-список семейств шрифтов, доступных на сайте или устройстве; `size` — положительный размер в пикселях; `color` — цвет в формате `#RRGGBB`. Обязателен только `text`, остальные поля по умолчанию имеют значения из примера. Без файла или с пустым текстом подписи нет. Изменения читаются при сборке; в локальном режиме обновите страницу после пересборки. Некорректный JSON или поле останавливает сборку с указанием файла.

## Настройки каждой банки

В каждой папке `public/assets/<категория>/jar` есть `settings.json`, заполненный текущими настройками этой банки. Редактируйте его перед сборкой и деплоем, например:

```json
{
  "scale": 1,
  "rotation": -30,
  "position": { "x": 12.5, "y": 14.814814814814813 },
  "mobilePosition": { "x": 25, "y": 9.803921568627452 },
  "indexAnchor": { "x": 95, "y": 95 },
  "seed": 11,
  "particleCount": 11,
  "blueberryCount": 13,
  "blueberrySize": 0.9,
  "particleSize": 1,
  "particleColor": "#ff8b10"
}
```

- `scale`: множитель размера банки; `1` — текущий размер, `1.2` — на 20% больше. Должен быть больше нуля.
- `rotation`: фиксированный угол в градусах; отрицательные значения наклоняют влево, положительные — вправо. Анимации вращения нет.
- `position.x/y`: положение центра банки в процентах ширины/высоты сцены на компьютере (ширина экрана больше 650 px). Координаты от `0` до `100`.
- `mobilePosition.x/y`: отдельное положение центра на телефоне при ширине до 650 px включительно, тоже в процентах сцены. Масштаб и угол общие для обоих режимов.
- `seed`: целое число от нуля, управляющее исходным распределением ягод и частиц, а также рисунком осколков.
- `indexAnchor.x/y`: положение центра индекса в процентах ширины/высоты изображения банки до поворота. `{ "x": 0, "y": 0 }` — левый верхний угол, `{ "x": 50, "y": 50 }` — центр, `{ "x": 100, "y": 100 }` — правый нижний угол. Можно задавать отрицательные значения и значения больше `100`, чтобы вынести индекс за границы банки. Обе координаты обязательны. Якорь учитывает размер и `scale` банки; на телефоне используется тот же якорь. Индекс остаётся горизонтальным и не участвует во вращении. Если удалить `indexAnchor`, используется прежнее положение справа внизу.
- `blueberryCount`: целое число от нуля, количество ягод в банке; `0` отключает ягоды. `null` или отсутствие параметра возвращает автоматический расчёт по площади стекла. Открытие категории работает и без ягод.
- `blueberrySize`: множитель размера ягод. При `1` диаметр каждой ягоды равен 10% ширины исходного изображения банки; `0.9` — 9%, `1.5` — 15%. Значение больше нуля. Во всех семи файлах записан фактический текущий размер ягод. Если параметр отсутствует, размер подбирается автоматически.
- `particleCount`: целое число от нуля, количество частиц свечения внутри банки; `0` отключает их.
- `particleSize`: множитель текущего размера частиц свечения: `1` — исходный размер, `2` — вдвое крупнее, `0.5` — вдвое меньше. Значение больше нуля. Разброс размеров отдельных частиц и пульсация сохраняются.
- `particleColor`: цвет внутреннего свечения в формате `#RRGGBB`, например `#66aaff` или `#b388ff`. Значение `#ff8b10` сохраняет исходный янтарный градиент. Внешняя пыль при наведении задаётся отдельно в коде.
- `particleZone`: положение и размеры зоны полёта частиц внутри банки, в процентах полного изображения `base.webp`. `x` и `y` задают левый верхний угол, `width` и `height` — ширину и высоту. Например, `{ "x": 25, "y": 50, "width": 50, "height": 30 }` задаёт прямоугольник от 25% до 75% по горизонтали и от 50% до 80% по вертикали. Размеры должны быть больше нуля, вся зона должна помещаться в изображении.
- `particleZone.polygon`: необязательные точки `[x, y]` от `0` до `1`, заданные относительно самой зоны. Меняйте положение и размеры, чтобы переместить или масштабировать контур целиком; отдельные вершины удобно править в локальном редакторе. Сохранённый полигон полностью определяет траектории и обрезку свечения, без пересечения с исходным контуром стекла или прозрачностью изображения. Если удалить `polygon`, зона станет прямоугольной. Если удалить весь `particleZone`, используется исходная стеклянная область. Настройка влияет на внутреннее свечение; область движения SVG-ягод и внешняя пыль остаются отдельными.

Явно заданный размер ягод сохраняется: если указанное количество не помещается в стекле, показываются ягоды, которые удалось разместить без пересечений, с предупреждением в консоли. Уменьшите `blueberrySize` или `blueberryCount`, чтобы поместились все ягоды. Частицы изначально равномерно заполняют площадь `particleZone`, включая выступы вогнутого полигона, затем плавно перемещаются по всей зоне и отражаются от её сторон и углов. Отступ при отскоке учитывает полный размер свечения с пульсацией. Слишком крупные частицы, не помещающиеся в заданной зоне, пропускаются.

Можно удалить отдельный параметр или весь файл: для отсутствующих значений используется автоматическая раскладка и исходные настройки. Явно заданные координаты остаются закреплены за банкой, даже если добавить другую категорию. При добавлении новой банки можно создать её собственный `jar/settings.json` с теми же полями. Повторный экспорт PSD сохраняет этот файл.

`npm run dev` пересобирает сайт после изменения настроек; обновите страницу. Для публикации выполните новую сборку (`npm run build`) и деплой. Настройки читаются во время сборки. Ошибка JSON, неизвестный параметр или некорректное значение останавливают сборку с указанием файла и проблемного поля.

## Просмотр

Для визуального редактирования зон частиц запустите `npm run jar-editor` и откройте http://127.0.0.1:5174. Перетаскивайте вершины и нажмите **Save**: контур запишется в `settings.json` выбранной банки. Локальный редактор расположен в `tools/jar-contour-editor` и не входит в сборку для Pages. Подробности — в `tools/jar-contour-editor/README.md`.

- Наведите курсор на банку: рядом появляется жирное название категории. Подпись выбирает свободное место возле банки; VERONICA остаётся в центре. Банки плавно увеличиваются с размерами экрана; на телефоне их размер зависит от ширины, на компьютере — от ширины и высоты окна.
- Нажмите на банку: откроется категория с выбором проекта по названиям сверху. В карусели отображается одна полная секция выбранного проекта. Весь экран просмотра, включая навигацию, помещается в текущую высоту окна без вертикальной прокрутки. Раскладка заранее рассчитывается по записанным при сборке пропорциям изображений и видео и строит плотную мозаику контейнеров с одинаковыми зазорами: 10 px на широком поле, 6 px на узком. Медиа заполняют контейнеры целиком; несовпадающие края слегка обрезаются по центру. Алгоритм выбирает раскладку с наименьшей обрезкой. При открытии отдельной работы на весь экран она показывается целиком.
- Контрастные круглые стрелки по бокам карусели (по центру высоты), точки под композицией, клавиши ←/→ и горизонтальные свайпы переключают секции. Для стрелок оставлены отдельные боковые поля, чтобы они не перекрывали работы. В каждом проекте собственная карусель; при выборе другого проекта открывается его первая секция. Изображения и видео загружаются только для текущей секции. Видео воспроизводятся без звука по кругу и приостанавливаются при открытии полноэкранного просмотра.
- На странице остаются названия категории и проектов и кнопки-символы. Нажмите на изображение или видео для полноэкранного просмотра. Кнопки и стрелки клавиатуры переключают отдельные работы выбранного проекта; Escape закрывает просмотр, повторный Escape — категорию.
- Удерживайте банку около 390 мс и двигайте курсором, чтобы стереть внутреннее свечение. Оно возвращается после отпускания или через пять секунд.
- В каждой банке движутся ягоды из `public/blueberries/base.svg`: количество и размер задаются в settings.json каждой банки; при blueberryCount: null количество рассчитывается по площади стеклянной зоны. Стартовые позиции распределяются по зоне с учётом этикетки. У большой круглой банки `jar-6.psd` (`digital`) контур охватывает стекло от плечиков под тканью до дна. Ягоды отскакивают от стекла и друг от друга без перекрытий; режим `multiply` и лёгкая прозрачность сохраняют фактуру основы, чтобы черника выглядела внутри банки. Банки неподвижны; исходные углы от −30° до 30° заданы в индивидуальных settings.json. Номера закреплены в постоянных местах рядом с банками и не участвуют во вращении; их положение пересчитывается только при изменении размеров макета. Каждая ягода также имеет свой поворот. Общая плотность ягод удвоена. Тот же SVG используется при вылете и возвращении; анимация начинается из текущего положения и размера одной из ягод. При вылете ягода увеличивается и делает шесть оборотов по часовой стрелке за 1,45 секунды. При уменьшении движения ягоды неподвижны; скрытая вкладка приостанавливает симуляцию.
- Нажмите **VERONICA** или **ABOUT**, чтобы открыть CV. Tab, Enter и Space поддерживаются; настройки уменьшения движения учитываются.

## Deploy to GitHub Pages

The workflow in `.github/workflows/deploy.yml` builds and deploys whenever you push to `main` or `master`, and supports manual runs from **Actions**. The asset catalog is scanned by the Vite plugin on each build, so new folders are included automatically. All work files in public/assets are copied into dist and included in the GitHub Pages artifact.

1. Push the project and the contents of `public/assets` to a GitHub repository.
2. Open **Settings → Pages** and select **GitHub Actions** under **Build and deployment → Source**.
3. Push to `main` or `master`, or manually run **Deploy to GitHub Pages** from **Actions**.
4. Open the published URL shown in the workflow's `deploy` job or **Settings → Pages**.

Vite reads the base path from GitHub Pages. Repository sites, `username.github.io` and custom domains all use the appropriate asset URLs. For a custom domain, configure it in **Settings → Pages** and add the matching DNS records.
